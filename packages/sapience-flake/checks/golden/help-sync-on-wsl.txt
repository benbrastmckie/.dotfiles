Linux notes: scheduled sync is systemd.user (sapience-sync.timer), not launchd.
  schedule: hourly
  status:   systemctl --user status sapience-sync.timer
  pause:    systemctl --user disable --now sapience-sync.timer
  run now:  systemctl --user start sapience-sync.service

WSL2 detected. The timer above is DEFINED but may never FIRE here.
  WSL needs two one-time steps before any systemd --user timer can fire:
    1. put [boot] systemd=true in /etc/wsl.conf, then run: wsl --shutdown
    2. loginctl enable-linger testuser
  Until both are done, 'systemctl --user status' reports no user manager
  and the only sync that happens is the one you run: sapience sync
