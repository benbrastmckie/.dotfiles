**BLOCKER (environment/permission, not a packaging defect)**: `sudo nixos-rebuild switch
--flake .#hamsa` is required to activate the NixOS-integrated home-manager generation, which is
the ONLY mechanism this host's shell startup chain (`/etc/profile` -> generated
`set-environment`) uses to auto-source `home.sessionVariables` into a plain login shell --
confirmed by inspecting `/etc/profile`, `/etc/bashrc`, `~/.profile` (elan PATH only), and
`~/.bashrc` (does not exist): none source `~/.nix-profile/etc/profile.d/*.sh`, which is where the
standalone home-manager path's `hm-session-vars.sh` lives. `sudo` is categorically blocked in
this agent session (`sudo -n true` -> "Permission ... has been denied" from the harness itself,
not a sudoers/password failure). This is a sandbox boundary of the implementing agent, analogous
to other user-only/root-gated operations in this repo's rules.

**Recommendation for the user**: run `sudo nixos-rebuild switch --flake .#hamsa` (or the repo's
`./scripts/update.sh` if it wraps both paths) to make `COMPARATOR_LANDRUN` auto-available in new
login shells. This is a normal, expected follow-up step, not a sign of broken packaging -- the
value is already correct and verified by `nix eval`.
