# Phase 4 Handoff: packages/comparator.nix real pinned derivation

**Immediate Next Action**: Phase 6 (Home Manager wiring + rebuild), then Phase 7 (fixture
verification).

**Current State**: Phase 4 completed. `packages/comparator.nix` builds as a real Nix derivation
(NOT a wrapper), fully offline (path-style lean4export require, per Phase 3's proven recipe),
using `lean-toolchain-bin` (Phase 2) as `nativeBuildInputs` for the build step only. Registered
in `overlays/unstable-packages.nix`. Behaviorally verified:
- `nix build` succeeds with real hashes for both `fetchFromGitHub` sources.
- `$out/bin/comparator` exists; running it with `--help` gives the same real, documented
  no-help-flag behavior as lean4export (`uncaught exception: no such file or directory`, exit 1,
  since `comparator`'s CLI unconditionally treats argv[0] as a config file path) -- this is
  expected/real execution, not a build defect; the actual behavioral demonstration is deferred to
  Phase 7's real fixture runs (`lake env comparator config.json`), which is the acceptance bar
  the task actually specifies.
- `$out/share/comparator/tests/projects/` contains all fixture triples including
  `simple_mismatch`.
- `$out/share/comparator/scripts/fake-landrun.sh` present and executable.

**Key Decisions Made**:
- comparator pinned at `2312244ac716564a61cc0bf4e107d9abf1757a61` (current `master` HEAD as of
  this packaging).
- Real hashes: comparator src `sha256-Y1mEW2oM3AqhmbcFmVgUModxTeHI33rZKVLabw06A44=`, lean4export
  src `sha256-2Ya3ZY47CSu7lHbJFwZWeqOMCipp6ykzFEwuojV8tT8=`.
- `fetchFromGitHub`'s default `name` is the generic string `source` for both fetches, which
  collided when both are listed in `srcs` (`stdenv`'s multi-source unpack copies each into a dir
  named after the store path's derivation name) -- fixed by setting an explicit distinct `name`
  on each `fetchFromGitHub` call. A genuine implementation-time discovery not anticipated by the
  Phase 3 recipe text (Phase 3's scratch harness used plain `cp -r`, not `stdenv`'s `srcs`
  mechanism, so this collision didn't surface until Phase 4).
- `lean-toolchain-bin` is `nativeBuildInputs` ONLY -- comparator's runtime `bin/comparator` is
  NOT wrapped with a fixed PATH; it relies on the ambient PATH at invocation time (normally
  elan's per-project shims), matching comparator's own README assumption and avoiding a
  wrong-toolchain trap for callers checking non-`v4.34.0-rc2` projects.

**Deviations from Plan**: None beyond the `name`-collision fix, an implementation-time discovery
rather than a plan-scope deviation (same files, same approach).

**What NOT to Try**: Don't expect `comparator --help` to print conventional usage text -- like
lean4export, it has none; don't try to fetchFromGitHub two sources into one `srcs` list without
distinct `name`s.
