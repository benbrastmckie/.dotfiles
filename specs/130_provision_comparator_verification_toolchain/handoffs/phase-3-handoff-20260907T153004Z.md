# Phase 3 Handoff: offline lake-dependency vendoring proof

**Immediate Next Action**: Phase 4 (packages/comparator.nix real pinned derivation), transcribing
the recipe below rather than re-deriving it.

**Current State**: Phase 3 completed via scratch harness in /tmp (not committed -- this phase is
explicitly scratch/experimental per the plan). Offline vendoring via a `path`-style Lake require
works cleanly; no FOD fallback needed.

**Recipe confirmed working** (verified twice: once against elan-managed v4.34.0-rc2, once against
the Phase 2 Nix-packaged lean-toolchain-bin, both under `unshare -rn` with network confirmed
blocked):
1. Fetch `leanprover/comparator` @ `2312244ac716564a61cc0bf4e107d9abf1757a61` (current master HEAD
   as of this packaging).
2. Fetch `leanprover/lean4export` @ `cacf989bd75f608700820f6afc595f32e7a99a4d` (the exact commit
   Comparator's own stock `lake-manifest.json` already resolves `rev = "master"` to).
3. Place both in sibling writable directories.
4. Rewrite comparator's `lakefile.toml` `[[require]]` block from
   `scope = "leanprover" / name = "lean4export" / rev = "master"` to
   `name = "lean4export" / path = "../lean4export"`.
5. Delete `lake-manifest.json` (lake regenerates one locally with no network access needed).
6. Put a Lean toolchain matching `v4.34.0-rc2` (Phase 2's `lean-toolchain-bin`, not elan) on PATH.
7. `lake build lean4export comparator` -- completes all 20/20 jobs offline.

**Key Decisions Made**: Path-style require is sufficient; the documented FOD fallback (a
network-permitted fixed-output derivation for the whole comparator build) was evaluated as a
contingency only and is NOT used -- stating this explicitly per the task's "state the reasoning
either way" instruction (recorded here and to be cross-referenced in Phase 8's
packages/README.md).

**Deviations from Plan**: None.

**What NOT to Try**: Don't try to keep Comparator's original git-based `[[require]]` block with a
pre-populated `.lake/packages/lean4export` directory and hope lake accepts it silently -- untested
and unnecessary; the `path`-style require is simpler and confirmed to work.
